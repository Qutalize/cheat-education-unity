# 各チートの実装解説（TPS_example / Multiplayer Third Person Gameplay）

このプロジェクトに実装したチートは、すべて **テンプレート本体が実際に使っている値・関数を
書き換える／利用する**ことで動く「本物の挙動」です。張りぼて（見た目だけ）ではありません。
各チートが「どのコードで、テンプレートのどこを触って成立しているか」を対応表にまとめます。

> 前提: すべて `CheatUtil.cs`（自分のプレイヤー・武器・照準コンポーネントをリフレクションで特定）を
> 経由します。これは現実のチートが「自分のプレイヤー構造体／武器構造体のアドレスを探す」工程に対応。

## 1. ESP（F2）— 情報を「読む」チート
- **実装**: `NetPlayerRegistry` が `NetworkManager.Singleton.SpawnManager.SpawnedObjects` を走査し、
  自分以外のプレイヤー／ボットの `transform.position`・`CoreStatsHandler.GetCurrentValue(StatKeys.Health)`
  を取得。`EspOverlayCheat` が `Camera.main.WorldToScreenPoint` で画面に枠・体力バーを描く。
- **なぜ本物か**: NGO は既定で全プレイヤーを全クライアントへ複製し `NetworkTransform` で位置同期する。
  壁の裏でも座標がメモリにある、という事実をそのまま利用している。描画も深度も触らない。
- **対策**: サーバーが見えない敵を送らない（`ServerVisibilityFilter` / `NetworkHide`）。

## 2. ウォールハック（F3）— 深度テスト無効化
- **実装**: 敵の `SkinnedMeshRenderer`（`Armature_Mesh`）を毎フレーム複製し、
  `CheatEducation/XRay`（`ZTest Always`）マテリアルで重ね描き。`SkinnedMeshRenderer.BakeMesh` で
  現在ポーズを焼いて追従。
- **なぜ本物か**: 「壁より奥は描かない」深度比較を `Always` にすり替える＝実在のタイプA
  ウォールハックの効果を GPU ステートで再現。本体プロジェクト(C++/DX12)の `m_enemyDepthAlwaysPSO` と同型。
- **対策**: 同上（送らない）／描画ステート門番。

## 3. エイムボット（F4）— サイレントエイム（照準ターゲット上書き）
- **発射の実コード**（`WeaponController.HandleFirePressed` / `ModularWeapon.Update`）:
  ```
  fireDirection = (AimController.PreciseAimTargetPosition - muzzle.position).normalized
  ```
  `PreciseAimTargetPosition` は `AimController` がカメラのレイキャストで求め
  `NetworkVariable m_NetworkedPreciseAimPosition` に保存している「照準の当たり先」。
- **実装**: `AimbotCheat` が毎 `LateUpdate` に、その NetworkVariable をリフレクションで取得し
  `.Value = 最寄りの敵の胸(AimPoint)` に上書きする。→ 発射方向が muzzle→敵になり
  `HitscanShooting` のレイが敵に命中。**カメラ（視点）は動かさない＝サイレント**。
- **なぜ本物か**: メモリ書換系エイムボットの典型「照準ターゲット座標を書き換える」そのもの。
  ノースプレッド(F5)併用で必中。`onlyWhileFiring`（撃つ間だけ吸着）で自然に見せられる。
- **注意**: NetworkVariable 書込はホスト(Start Host)で確実。`requireLineOfSight` OFF なら壁越しにも当たる。
- **対策**: サーバーが命中を再検証（撃った側の主張を信じない）＝レッスン02/05。

## 4. ノーリコイル＋ノースプレッド（F5）— 数値ゼロ化
- **実装**: 自分の `ModularWeapon` が参照する `WeaponData`（ScriptableObject）の
  `recoil` `minSpreadAngle` `maxSpreadAngle` `spreadIncreasePerShot` を 0 に書き換え、
  `ModularWeapon.Initialize(data)` で `SpreadHandler` を再初期化して即反映。OFF で元の値へ復元。
- **なぜ本物か**: 反動・拡散は WeaponData の float が唯一の源。`HitscanShooting.ApplySpread` は
  `spreadAngle<=0` のとき素の方向をそのまま撃つ＝ど真ん中。Cheat Engine で反動/拡散を 0 固定するのと同じ。

## 5. ダメージ強化（F6）— float 倍化
- **実装**: `WeaponData.weaponDamage ×= 倍率`。`HitscanShooting` が `hittable.OnHit` に渡す
  `context.damage` が増える＝一撃必殺。OFF で復元。
- **なぜ本物か**: ダメージ値の源はこの 1 個の float。メモリ上のダメージ改変そのもの。
- **対策**: ダメージ計算をサーバーで行う（クライアントの値を信じない）。

## 6. 無限弾（F7）— NetworkVariable フリーズ
- **実装**: 自分の `AmmoHandler` の private `NetworkVariable<int> m_CurrentClipAmmo` を
  リフレクションで取得し、毎フレーム `m_ClipSize` に戻す。
- **なぜ本物か**: 弾数の同期変数を最大値に freeze する＝Cheat Engine の値固定と同じ。
  このゲームはオーナー（自分）が弾数を書けるので通る（ホスト時確実）。

## 7. スピードハック＋ハイジャンプ（F8）— 移動値倍化
- **実装**: 自分の `CoreMovement.moveSpeed / sprintSpeed / jumpHeight`（public フィールド）を倍化。OFF で復元。
- **なぜ本物か**: 移動速度・ジャンプ高さの源はこれらの値。しかも `NetworkTransform` が
  **AuthorityMode=Owner（クライアント権威）** なので、自分が計算した速い移動をサーバーが信じ、
  他プレイヤー画面でも速く見える。＝「クライアント権威だと速度改変が通る」実例。
- **対策**: `NetworkTransform` を Server Authority に＋移動量検証（rubber-band）＝レッスン04/05。

## 8. 無敵（F9）— 体力フリーズ
- **実装**: 自分の `CoreStatsHandler` の体力を毎フレーム `ModifyStat(StatKeys.Health, max-cur)` で満タンへ。
- **なぜ本物か**: 体力は `NetworkList<RuntimeStat>`（オーナー書込）。自分が所有者なので書ける＝
  被弾しても実質死なない。Cheat Engine の体力 freeze と同じ。
- **対策**: サーバーが体力の正本を持つ＝レッスン05。

---

## まとめ（この教材の主張）

- F5〜F9 は**クライアントが持つ値／計算を書き換える**ことで成立する。
  ＝「クライアントが持っている情報と計算はすべて改変される」という原則の実演。
- F8（速度）・F6/F9（ダメージ/体力）が通るのは、このテンプレートが
  **クライアント権威・オーナー書込**の素朴な実装だから。
  → 根本対策は **サーバー権威**（送らない・サーバーで計算する）。レッスン05 に接続。
