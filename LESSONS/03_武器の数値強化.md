# レッスン03 武器の数値強化

**チート**: ダメージ・連射速度・弾数・射程・反動を勝手な値に書き換える。無限弾・ノーリコイル。
**対策**: 武器パラメータの正本をサーバーが持つ。ダメージ計算・弾数消費をサーバーで行う。

---

## 1. チートの説明

Cheat Engine（外部）や dnSpy（`Assembly-CSharp.dll` を書き換え）でよくやられる、
最も古典的なチート。狙う値:

| 値 | 効果 |
|---|---|
| damage | 1 発で即死 |
| fireRate / fireInterval | フルオートマシンガン化 |
| ammo / magazineSize | リロード不要・無限弾 |
| range / maxDistance | どこからでも当たる |
| recoil / spread | ノーリコイル・ノースプレッド＝反動と拡散ゼロ |

この教材では外部プロセスの代わりに**同一プロセス内のリフレクション**（`Scripts/Reflect.cs`）で
書き換える。「メモリ上の float を書き換える」のと本質的に同じことを、安全な範囲で体験する。

---

## 2. なぜ効くのか（NGO の仕組みから）

問題は**「誰がその数値を持ち、誰がその数値で計算するか」**。

- 武器の数値が **クライアントの MonoBehaviour のフィールド**にある → 書き換え放題。
- ダメージ適用が **クライアントで計算されてから `ApplyDamageServerRpc(amount)` でサーバーへ送られる**
  → `amount` を 9999 にできる。
- 弾数が **クライアントの `int ammo`** で、`FireServerRpc` を投げる条件が「ammo > 0」だけ
  → ammo を毎フレーム戻せば無限弾。

**サーバーが数値の正本を持ち、サーバーが計算していれば**、クライアントのフィールドを
いくら書き換えても「表示が変わるだけ」で結果は変わらない。
03 は「サーバー権威で完全に潰せる好例」。

---

## 3. テンプレートのどこを見るか

```bash
grep -rn "damage\|Damage\|fireRate\|fireInterval\|cooldown\|ammo\|Ammo\|magazine\|recoil\|spread\|ScriptableObject\|WeaponData\|WeaponConfig" Assets/Shooter --include=*.cs
```

確認すること:
- 武器の数値は **ScriptableObject**（例 `WeaponData.asset`）か、プレハブ／スクリプトの
  serialized フィールドか
- ダメージを適用する行はどこか。その前後に `if (IsServer)` があるか、`ServerRpc` の
  引数に「ダメージ量」が入っているか「発射した事実」だけか
- 弾数は `NetworkVariable<int>` か、ただの `int` か
- リロード処理はサーバーで走るか

## 4. チートの実装

### 使うスクリプト
`Scripts/WeaponBuffCheat.cs`（前バージョンから流用・NGO 向けに調整）

- `weaponScript` に武器スクリプト（未指定ならシーンから自動探索）
- 倍率スライダ: ダメージ / 発射間隔 / 弾数 / 射程
- トグル: ノーリコイル / ノースプレッド
- ON にした瞬間の値を保存し、倍率を掛けて上書き。毎フレーム書き戻す
  （ゲームが消費・補充するため）。OFF で復元。

### 手順
1. 調査手順で武器スクリプトの型名とフィールド名を確定。
2. `WeaponBuffCheat` の「メンバ名を明示」欄にフィールド名を入れる（自動探索が外す場合）。
3. Play。F1 →「武器強化」ON。連射・即死になることを確認。

---

## 5. 対策の実装

### 対策1: 武器パラメータをサーバー権威に
- 武器の数値は **ScriptableObject に集約**し、**サーバーだけがそれを参照して計算**する。
- クライアントの武器スクリプトが持つ数値は**表示・演出専用**（UI の連射音・反動アニメ）に格下げ。
  クライアントがそれを書き換えても、ダメージ・弾数・レートには影響しない。

### 対策2: ダメージ計算をサーバーで
```csharp
[Rpc(SendTo.Server)]
void FireRpc(Vector3 origin, Vector3 dir, RpcParams p = default)
{
    ulong shooter = p.Receive.SenderClientId;
    if (!ServerCooldownOk(shooter)) return;                 // レート検証（02 と共通）
    if (!ServerRaycast(origin, dir, out var victim)) return; // 命中判定もサーバー
    float dmg = _weaponData.damage;                          // ★正本はサーバーの SO
    victim.GetComponent<CoreStatsHandler>().ApplyDamageServer(dmg);
}
```
クライアントは `dmg` を送らない。**送る値を減らせば、減らせる余地も消える**。

### 対策3: 弾数をサーバー権威に
`NetworkVariable<int> Ammo` を **書き込み権限サーバー**で持つ。
```csharp
NetworkVariable<int> Ammo = new(30, NetworkVariableReadPermission.Owner,
                                    NetworkVariableWritePermission.Server);
```
発射のたびにサーバーが `Ammo.Value--`。0 なら `FireRpc` を無視。
クライアントが自分の `int` を 999 にしても、サーバーの `Ammo` は減り続ける。

### 対策4: 反動・拡散をサーバー判定に反映
「命中判定用の方向」にサーバー側で拡散を加える（クライアントの見た目の拡散とは別に、
サーバーが `_weaponData.spread` で散らす）。ノースプレッドにしても命中判定は散る。

## 6. 体験・観察手順

| 手順 | 期待される結果 |
|---|---|
| 対策なし・武器強化 ON | 1 発即死・無限連射・リロードなし |
| 武器データをサーバー SO 化＋ダメージをサーバー計算 | クライアントで damage=9999 にしても、相手の体力は正規ダメージしか減らない |
| 弾数を `NetworkVariable`(server) 化 | クライアントで ammo を戻しても撃てなくなる（サーバーの残弾 0） |
| F1 パネルのステータス | 「フック中のメンバ: N」は出るが、ゲーム結果に反映されない |

---

## 7. 対策の限界

- **ほぼ無い（これはサーバー権威で完全に潰せる）**。数値チートが怖いのは
  「クライアントに計算を任せている」設計だからで、計算をサーバーに移せば消える。
- 残る問題は**コスト**（全発射をサーバーで判定＝レッスン02 と同じ負荷）と、
  **正しく移せているかの網羅性**（一箇所でもクライアント計算が残るとそこが穴）。
- クライアント側の武器数値を**難読化**（`ObscuredFloat` 等）しても、それは
  「クライアント計算のままにしておくための延命策」でしかなく、根本策は
  「クライアントで計算しない」こと。
