# レッスン00 導入とセットアップ

---

## この教材で学ぶこと

シューティングゲームに、実際にあるチートを **1 つずつ自分で実装** して
「チートはどういう仕組みで動くのか」を体で理解する。そのうえで
**Unity（Netcode for GameObjects）でどう対策するか** を、これも実装して確かめる。

最終的に到達したい理解:

> クライアント（プレイヤーの PC）が「持っている情報」と「行っている計算」は、
> 難読化しても整合性チェックを足しても、いずれ読まれ・書き換えられる。
> チート対策を「クライアントを賢くする」問題として解こうとすると勝てない。
> **「サーバーが何を送り、何を信じるか」の問題**に置き換えたとき初めて構造的に勝てる。

---

## 規約・倫理（毎回読む）

### やってよいこと
- **自分の PC の中だけで完結する実験。** Multiplayer Play Mode（1 台で仮想プレイヤー）か、
  同じ LAN 内で自分が立てたセッションに、自分（と、合意した仲間）だけが接続する。
- 提供スクリプトを読んで改造し、動作を観察する。

### やってはいけないこと
- **公開サーバー・オンラインマッチメイキング・他人が運営するゲームでの実行。**
  日本では電子計算機損壊等業務妨害罪・不正アクセス禁止法などに触れうる。
- Unity Gaming Services（Relay / Lobby / Matchmaker）を使った**他人と混じるセッション**での実行。
  → セッション作成時は必ず「ローカル / ダイレクト接続」を選ぶ。
- 汎用チートの作成・配布（任意のゲームに効く DLL 注入・フック）。この教材は
  **同一プロジェクト内で自分のオブジェクトを操作する範囲**に限定している。
- テンプレート本体（Unity の C#・アセット）の再配布。教材として配ってよいのは
  **自分が書いたスクリプト・差分・手順・スクリーンショット**まで。

### なぜこの線引きなのか
チートの「効果」を自分のローカルで再現して仕組みを理解することと、
それを他人のゲーム体験を壊すために使うことは、技術的には地続きでも
**倫理的・法的にはまったく別**。この教材は前者だけを扱う。

## テンプレートの構造を把握する

テンプレートは 3 層に分かれている（公式ドキュメント「Project Overview」より）:

| 層 | フォルダ | 中身 |
|---|---|---|
| **Core（土台）** | `Assets/Core/` | 入力と移動 / カメラ / ネットワーク / 体力とスタミナ |
| **Platformer** | `Assets/Platformer/` | ジャンプ・コイン（本教材では未使用） |
| **Shooter** | `Assets/Shooter/` | 武器・発射体・エイム ← **本教材の主対象** |

プレイヤーは `CorePlayer` プレハブ（＋ Shooter 版の派生プレハブ）で、
おおむね次のコンポーネントを持つ:

- `NetworkObject` … NGO の同期単位
- `CorePlayerManager` … 各システムの統括
- `CoreInputHandler` … 入力を拾って GameEvent を発行
- `CoreMovement` … 速度・物理
- `CoreStatsHandler` … 体力・スタミナ
- `CoreCameraController` … 視点モード切替
- Shooter 版で追加される武器・エイム関連スクリプト

> ★ 実際のクラス名・メソッド名・フィールド名は Unity のバージョンやテンプレート更新で
> 変わる。以降のレッスンは上記の名前を前提に書くが、**必ず自分のプロジェクトで確認する**。
> その調査手順を次に示す。

## 調査手順（すべてのレッスンで使う技）

### A. スクリプトを名前で探す

Unity の Project ウィンドウ検索窓に `t:script movement` のように打つと
スクリプトを絞れる。または OS のファイル検索で `Assets/Shooter` 以下の `.cs` を見る。

コマンドラインが使えるなら（プロジェクトのルートで）:

```bash
# 武器・発射・ダメージ関連
grep -rn "class .*Weapon\|class .*Projectile\|Damage\|FireRate\|Ammo" Assets/Shooter --include=*.cs
# 移動速度
grep -rn "moveSpeed\|MoveSpeed\|speed\|velocity" Assets/Core --include=*.cs
# 体力
grep -rn "Health\|health\|TakeDamage\|Die" Assets/Core --include=*.cs
# ネットワーク権限（サーバー権威かどうかの手がかり）
grep -rn "ServerRpc\|Rpc(SendTo\|IsServer\|IsOwner\|NetworkVariable\|OwnerAuthoritative\|AuthorityMode" Assets --include=*.cs
```

### B. プレハブのコンポーネント構成を見る

`Assets/Shooter/` 以下でプレイヤープレハブ（`Shooter Player` など）を選び、
Inspector で以下を確認:

- `NetworkObject` があるか
- `NetworkTransform` の **Authority** が `Server` か `Owner` か
  （04 レッスンで最重要。Owner なら「クライアントが位置を自由に送れる」＝ハックしやすい）
- 武器・エイムのコンポーネント名
- 体力コンポーネントと、その値が `NetworkVariable` か普通の `float` か

### C. シーンの NetworkManager を見る

Shooter シーン（またはセッション対応シーン）の `NetworkManager` を選び:

- **Network Transport**（Unity Transport）の接続先設定
- **Default Player Prefab**
- **Connection Approval** の有無
- **Tick Rate**

### D. 実行時にログで確かめる

「このメソッドはサーバーで呼ばれているのかクライアントでか」を知りたいときは、
一時的に `Debug.Log($"{name} fire IsServer={IsServer} IsOwner={IsOwner}");` を仕込む。
これが 02〜04 の対策実装で効いてくる。

## 操作を確認する

`Assets/Core/` 以下の Input Actions アセット（`.inputactions`）をダブルクリックすると
アクション一覧が見える。`Move` `Look` `Fire` `Aim` `Jump` などのバインドを控えておく。
（既定はおおむね WASD / マウス / 左クリック / 右クリック）

## セッション対応シーンの作り方（`MS` 付きが無い場合）

1. Shooter シーンを複製して `[BB] Shooter MS` にリネーム。
2. Multiplayer Services Building Blocks のセッション UI プレハブ
   （`Assets/` 内を `Session` で検索）をシーンに配置。
3. `NetworkManager` が無ければ追加し、Transport を **Unity Transport**、
   接続先を `127.0.0.1:7777` に。
4. Default Player Prefab に Shooter のプレイヤープレハブを設定。
5. セッション UI で「ローカル接続 / Relay 無効」を選べるようにする
   （Building Blocks の設定に「Connection Type: Direct」等がある）。

詳細はテンプレート付属ドキュメント「Playing the Sample Scenes」を参照。
