# レッスン04 スピードハック・無敵・テレポート

**チート**: 移動速度を倍化 / 座標を直接書き換えて瞬間移動 / 体力を毎フレーム最大に戻して無敵。
**対策**: `NetworkTransform` を Server Authority にし、サーバーが移動量を検証する。体力を `NetworkVariable`(server) に。

---

## 1. チートの説明

| チート | 手口 |
|---|---|
| スピードハック | 移動スクリプトの `moveSpeed` を倍化。または `Time.timeScale` を上げて全体を加速 |
| テレポート | `transform.position` を直接書き換え（壁抜け・目標地点へ瞬間移動） |
| フライ / ノークリップ | 重力・コライダーを無効化して壁を通過 |
| 無敵 | 体力を毎フレーム最大値へ書き戻す（Cheat Engine の "freeze" と同じ） |

---

## 2. なぜ効くのか（NGO の仕組みから）

**`NetworkTransform` の Authority 設定**がすべてを決める。

### Owner Authority（クライアント権威）の場合
- **クライアントが自分の位置を計算し、サーバーへ「ここにいる」と送る。**
- サーバーはそれをほぼそのまま他クライアントへ中継する。
- → `transform.position` に何を入れても、`moveSpeed` を何倍にしても、
  **サーバーは「そういう位置にいる」と信じる**。スピードハックもテレポートも通る。
- 応答は軽快（自分の入力が即反映）だが、**チートし放題**。

### Server Authority（サーバー権威）の場合
- **クライアントは入力（移動スティックの値）だけ送る。**
- **サーバーが移動をシミュレートして位置を決め**、全員へ配る。
- → クライアントが `transform.position` を書き換えても、次のサーバー更新で
  正しい位置へ戻される（**rubber-banding**）。`moveSpeed` はサーバーが持つ値を使う。
- 自分の動きに一瞬のラグを感じる（クライアント予測＋補正で緩和する）。

体力も同じ。`NetworkVariable<float> Health` の**書き込み権限がサーバー**なら、
クライアントがローカルの値をいじっても無視される。書き込み権限が Owner なら無敵が通る。

---

## 3. テンプレートのどこを見るか

- プレイヤープレハブの `NetworkTransform` を選び **Authority** を確認
  （`Server` / `Owner` / テンプレートによっては `NetworkTransform` 派生の独自コンポーネント）。
- テンプレートが **distributed authority モード**（NGO 2.x の新モード）を使っている可能性。
  その場合「所有者＝権威」なので、既定ではクライアント権威に近い。
  `grep -rn "DistributedAuthority\|NetworkTopology\|SessionModeType" Assets --include=*.cs`
- `CoreMovement` が位置を動かすのは `IsOwner` ガードの中か、サーバーか。
- `CoreStatsHandler` の体力が `NetworkVariable` か、その Write 権限は誰か。

```bash
grep -rn "NetworkTransform\|AuthorityMode\|Authority\b\|NetworkVariable<.*[Hh]ealth\|timeScale" Assets/Core --include=*.cs
```

## 4. チートの実装

### 使うスクリプト
`Scripts/MovementCheat.cs`（旧 `PlayerBuffCheat` ＋ `TimeScaleCheat` を統合）

| 機能 | 実装 |
|---|---|
| スピードハック | `CoreMovement` の速度フィールドをリフレクションで倍化 |
| タイムスケール | `Time.timeScale` と `Time.fixedDeltaTime` を下げる（スロー）／上げる（加速） |
| テレポート | キー入力で `transform.position` を「カメラ前方 N m」へ or 保存地点へ |
| 無敵 | `CoreStatsHandler` の体力を毎フレーム最大へ書き戻す |
| フライ | `Rigidbody.useGravity=false` ＋ 上下入力で移動（コライダーはそのまま） |

### 手順
1. `CheatConsole` の GameObject に `MovementCheat` が自動で乗る。
2. `moveScript` に `CoreMovement`、`statsScript` に `CoreStatsHandler` を割当（自動探索も試みる）。
3. Play。F1 →「移動チート」ON。速度倍化・テレポートを試す。

## 5. 対策の実装

### 対策1: `NetworkTransform` を Server Authority に切り替える
- プレイヤープレハブの `NetworkTransform`（または独自の移動同期コンポーネント）の
  Authority を **Server** に。
- `CoreMovement` の位置更新を **サーバーで実行**するよう変更し、クライアントは
  `MoveInputServerRpc(Vector2 stick)` で入力だけ送る。
- クライアント側は**予測**（自分の入力を即座に反映）＋**補正**（サーバー位置とずれたら寄せる）を
  入れて操作感を保つ。NGO の `NetworkTransform` は補間を持つのである程度自動。

> テンプレートが distributed authority なら、まず **client-server（server authoritative）
> トポロジ**に切り替える（`NetworkManager` の設定）。これが 04 対策の前提。

### 対策2: サーバー側の移動量検証（`Countermeasures/ServerMovementValidator.cs`）
Server Authority にできない／予測がずれるケースの保険。サーバーで毎tick:

```csharp
float maxStep = maxSpeed * tickDelta * tolerance;   // この tick で動ける上限
if (Vector3.Distance(prevPos, reportedPos) > maxStep)
{
    // 異常: サーバーの正しい位置へ戻す（rubber-band）＋ログ
    transform.position = prevPos + (reportedPos - prevPos).normalized * maxStep;
    LogSuspicious(clientId, "speed/teleport");
}
```
テレポートは 1 tick の移動量が桁違いになるので確実に弾ける。
スピードハックは `maxSpeed` を少し超えるぶんを削る。

### 対策3: 体力をサーバー権威に
```csharp
NetworkVariable<float> Health = new(100, NetworkVariableReadPermission.Everyone,
                                        NetworkVariableWritePermission.Server);
```
ダメージは `ApplyDamageServer`（サーバーでのみ実行）で `Health.Value` を減らす。
クライアントがローカルの体力表示をいじっても、`Health` はサーバーが管理。

### 対策4: `Time.timeScale` 依存をなくす
ゲームロジック（当たり判定・クールダウン・移動）をサーバー時間 / `NetworkManager.ServerTime` で
回す。クライアントの `timeScale` は自分の描画にしか影響しなくなる。

## 6. 体験・観察手順

| 手順 | 期待される結果 |
|---|---|
| Owner Authority のまま・スピードハック ON | 本当に速く動ける。他プレイヤー画面でも速い |
| Server Authority に切替 | `moveSpeed` を倍化しても速くならない（サーバーの値で動く） |
| Server Authority ＋ テレポート実行 | 一瞬ワープするが即座に元の位置へ引き戻される（rubber-band） |
| `ServerMovementValidator` 有効・テレポート | Host コンソールに「client X: teleport 検知・補正」 |
| 体力を `NetworkVariable`(server) 化・無敵 ON | ローカル体力は満タン表示だが、被弾すると死ぬ（サーバーの Health が 0） |

---

## 7. 対策の限界

- **操作感とのトレードオフ**: Server Authority は予測＋補正の実装が必要。雑にやると
  「動きがカクつく」「入力が遅れる」。多くのカジュアルゲームが Owner Authority を選ぶのはこのため。
- **検証の閾値調整**: `tolerance` を緩めるとスピードハックが微妙に通り、厳しくすると
  ラグスパイク時に正規プレイヤーが引き戻される。ネットワーク品質のばらつきと戦うことになる。
- **予測の範囲**: クライアント予測を認める部分（自分の移動の見た目）には常に
  「少し先に進んで見える」隙がある。
- それでも **Owner Authority → Server Authority の切り替えだけで、スピード/テレポート/フライ/無敵の
  露骨なものは全滅する**。04 の対策は費用対効果が非常に高い。
