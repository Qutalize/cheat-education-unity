# レッスン02 エイムボットとホーミング

**チート**: 発射の瞬間に照準を最寄りの敵へ吸着させる（エイムボット）。または発射済みの弾を敵へ誘導する（ホーミング）。
**対策**: サーバーがヒットを再検証する。発射レートをサーバーが検証する。命中率を統計監視する。

---

## 1. チートの説明

- **エイムボット**: プレイヤーが撃つと、その瞬間だけカメラ／武器の向きを敵の当たり判定へスナップ。
  「エイムが完璧に上手い人」に見える。強さは調整でき、`スナップ距離`『反応角度』を絞ると検知されにくい。
- **ホーミング**: 弾（発射体）そのものの進行方向を毎フレーム敵方向へ曲げる。照準は動かさないので
  「弾がカーブして当たる」。ヒットスキャン（レイキャスト即着弾）の武器には使えず、
  発射体（Projectile）方式の武器に効く。

共通点: **狙い・弾道の計算がクライアントで行われている** から成立する。

---

## 2. なぜ効くのか（NGO の仕組みから）

テンプレートの Shooter レイヤーがどちらの方式かで話が変わる（調査手順3で確認）:

### A. クライアントがレイキャストして「当たった」をサーバーに報告する方式
```
[クライアント] Fire 入力 → カメラ前方へ Physics.Raycast → hit した相手を決める
            → SubmitHitServerRpc(targetNetworkId, hitPoint)
[サーバー]     受け取った targetNetworkId のダメージ処理をする
```
この場合、**クライアントが「誰に当たったか」を自由に主張できる**。エイムボットは
「向きを敵へ向けてからレイキャスト」するだけ。極端には向きすら要らず、
`SubmitHitServerRpc` に好きな相手を入れれば当たる（＝エイムボットを超えて「常時命中」）。

### B. クライアントは入力だけ送り、サーバーがレイキャストする方式
```
[クライアント] Fire 入力 + 現在の視線方向 → FireServerRpc(aimDirection)
[サーバー]     aimDirection でレイキャストして命中判定
```
この場合でも、**`aimDirection` はクライアントが作る値**。エイムボットは
「送る aimDirection を敵方向に差し替える」。サーバーは「その方向で撃ったことにする」しかない。
ホーミングは、発射体がクライアント側で動いてサーバーへ位置報告する設計なら曲げられる。

→ **どちらの方式でも「クライアントが方向・命中を決める」構造が残る限りエイムボットは成立する。**

---

## 3. テンプレートのどこを見るか

```bash
grep -rn "Raycast\|Linecast\|SphereCast\|ServerRpc\|Rpc(SendTo\|Projectile\|Hit\|Fire" Assets/Shooter --include=*.cs
```

確認すること:
- 武器はヒットスキャン（`Raycast`）か発射体（`Projectile` プレハブを `Instantiate`/`Spawn`）か
- 命中判定は **どこで** 行われるか（`IsServer` ガードの有無、`ServerRpc` の引数に「命中相手」が
  入っているか「方向」だけか）
- 発射体がある場合、その移動は誰が動かすか（`NetworkTransform` の Authority、
  クライアント予測の有無）
- 連射制御（クールダウン）が**クライアントの `float timer` だけ**か、サーバーでも見ているか

## 4. チートの実装

### 使うスクリプト
- `Scripts/AimbotCheat.cs` … Fire 入力を検知し、その 1 フレームだけカメラ回転を
  最寄り `NetPlayerRegistry` ターゲットへ Slerp（強さ・射程・コーン角を調整可能）
- `Scripts/HomingCheat.cs` … 新しく生成された発射体（名前/タグ/`Rigidbody` で判定）に
  `HomingSteer` を付け、速度ベクトルを敵方向へ曲げる

### 手順
1. `CheatConsole` の GameObject に `AimbotCheat` / `HomingCheat` が自動で乗る。
2. `AimbotCheat` の `aimAtTransformPath` に「敵の当たり判定にする子オブジェクト名」
   （胸のボーンやコライダー）を入れる。空なら `NetworkObject` の原点を狙う。
3. `HomingCheat` の `projectileNameContains` にテンプレートの発射体プレハブ名の一部を入れる
   （調査手順で確認。例 "Projectile" "Bullet" "Bolt"）。
4. Play。F1 →「エイムボット」ON。敵の方を**大まかに**向いて撃つと吸着する。

### コードのポイント（`AimbotCheat.cs`）
```csharp
// Fire が押された瞬間だけ、カメラ回転を敵へ寄せる。
if (firePressedThisFrame) {
    var target = registry.NearestVisibleOrAny(cam.position, cam.forward, coneAngle, range);
    if (target != null) {
        Vector3 dir = (target.AimPoint - cam.position).normalized;
        cam.rotation = Quaternion.Slerp(cam.rotation, Quaternion.LookRotation(dir), strength);
    }
}
```
「発射処理より前」に割り込む必要がある（`Update` の実行順 or 発射スクリプトへの
ラッパー）。調査手順Dのログで「Fire がどのタイミングで方向を読むか」を掴む。

## 5. 対策の実装

### 対策1: サーバー側ヒット検証（`Countermeasures/ServerHitValidator.cs`）
クライアントが `SubmitHitServerRpc(target, origin, dir)` を送ってきたら、サーバーが:

1. `origin` が **その client のプレイヤーの実際の位置**と近いか（`NetworkTransform` の値と照合）
2. `dir` と「client が最後に報告した視線方向」が大きく食い違っていないか
3. サーバー自身が `origin`→`dir` で `Physics.Raycast` し、`target` に本当に当たるか
4. 前回発射から**武器のクールダウン以上**経っているか（サーバーが時刻を持つ）

すべて通ったときだけダメージを適用。**「クライアントが当たったと言ったから当てる」をやめる**。

> 厳密には撃った瞬間の敵位置で判定する必要がある（**ラグ補償 / lag compensation**）。
> 過去数フレームの敵位置を保持し、client の RTT ぶん巻き戻して判定する。
> 雛形にはリングバッファのコメントを入れてある。

### 対策2: 連射レートのサーバー検証
`FireServerRpc` にサーバー側クールダウンチェックを入れる。武器の
`fireInterval` は**サーバーが持つ ScriptableObject** から読む（クライアントの値を信じない。03 レッスンと共通）。

### 対策3: 命中率の統計監視（事後検知）
サーバーで client ごとに「発射数 / 命中数 / ヘッドショット率 / 撃ってから命中までの反応時間」を
集計。人間離れした値（例: 反応 50ms 未満が連続、命中率 95%+）をログ・フラグ。
**これは"止める"のではなく"怪しい人を洗い出す"**。エイムボットは強さを下げると
検知を逃れられるので、統計監視は最後の網。

## 6. 体験・観察手順

| 手順 | 期待される結果 |
|---|---|
| 対策なし・エイムボット ON | 適当に撃っても当たる |
| `ServerHitValidator`（方向照合のみ）を有効化 | 「向きと弾道が食い違う」発射がサーバーログに出る／無効化される |
| `ServerHitValidator`（サーバー再レイキャスト）を有効化 | クライアントが「当たった」と言っても、サーバーの判定で外れていればダメージが入らない |
| ホーミング ON ＋ 発射体をサーバー権威に | 弾はクライアント画面で曲がるが、サーバーの弾は直進＝ダメージ計算に効かない |
| 統計監視 ON | F1 とは別に、Host のコンソールに「client X: 反応時間中央値 40ms（疑わしい）」 |

---

## 7. 対策の限界

- **ラグ補償の精度**: 巻き戻し量が RTT 推定に依存。推定を偽装されると誤判定の余地。
- **サーバー負荷**: 全発射をサーバーでレイキャスト＋巻き戻し＝人数 × 発射レートぶんのコスト。
- **統計監視は事後**: 検知までにラウンドは終わる。強さを絞ったエイムボットは統計的に人間と区別しづらい。
- **「入力の妥当性」は完全には検証できない**: 「その方向を向いて撃った」こと自体は
  サーバーから見て常に"あり得る"。エイムボットが人間の限界内（反応 150ms・命中率 60%）に
  収まるよう調整されると、サーバー検証・統計監視の両方をすり抜ける。
  → **完全な排除は不可能。攻撃コストを上げ、露骨なものを弾き、怪しいものを洗い出す**まで。
